# Servers: inventory, differences, merge (decision 1, 2026-10-16)

## What runs on :8000
- `realai-server = realai.server.app:main` (pyproject) and the docs (`uvicorn realai.server.app:app --port 8000`) point to the **structured server**, `realai/server/app.py` plus `router.py`.
- `realai/start_realai.bat` calls `realai.cli.realai_cli serve --port 8000`. That CLI has no `serve` subcommand in this tree, so treat `realai.server.app` as the :8000 default.
- When I checked (Oct 16, ~11:58 PM PT) nothing was listening on 8000/8001/8080/8890/8787/3000. Nothing was started or stopped.
- **Default :8000 behaviour is unchanged.** Every new route and the local SDXL handler are opt-in.

## Merge
- **One canonical legacy API: `realai/server/legacy_api.py`.** It is the union of all api_server phases. The only defs or routes missing from the Oct 10 live copy were:
  - `POST /v1/memory/recall` from `api_big_server`, ported to the current `MEMORY_ENGINE.retrieve`;
  - `_log_request_row` per-request sqlite logging from the RealAI-gold `clean_backup_20260708` stub, recovered as opt-in `REALAI_LOG_REQUESTS=1`, storing the prompt **hash** only.
  - The gold stub's `CLEAN_STUB_FLAG` canned replies, `_json_response`, `_html_response` and `_read_json_or_error` are superseded by the handler's `_send_response`, `_send_html` and `_read_body`, so they were not carried over.
- **Shims (module alias, `python -m` still works).** `realai/api_server.py` (Render/Vercel entry and `realai.api.index` unchanged), `realai/core/api_server.py`, `realai/plugins/api_server.py`, `realai/plugins/api_big_server.py`, and `realai/plugins/realai_local_server.py` (to `realai/server/realai_local_server.py`).
- **Structured :8000 server plus merged routes.** Set `REALAI_SERVER_MERGED_ROUTES=1` (default off). `router.dispatch_request` then forwards any path no structured route (or `REALAI_UNIFIED_ROUTES` route) handled to the legacy handler, in-process through `realai/server/legacy_bridge.py`. No extra socket is opened. On FastAPI, the same flag registers a last-position catch-all. Structured routes always win.
- **Local images.** `realai/local_sdxl.py` (SDXL-Turbo, diffusers + torch-directml, weights `C:\models\image\sdxl-turbo`) is brought in from the pushed `feat/local-image-sdxl-turbo` (9314a7c, files only; the bats are not included). `abilities/image_generation.py` takes that commit's local-only version: SDXL, then Pillow, with the xAI path removed. Both `/v1/images/generations` handlers use `local_sdxl.handle_images_generations` when `REALAI_IMAGES_LOCAL_SDXL=1` and the weights exist. The structured router otherwise keeps its placeholder; the legacy API otherwise keeps `model.generate_image`. SDXL needs about 7 GB VRAM, so stop the 14B first.
- **Bug fix.** `realai/server/app.py` referenced an undefined `logger` on its error path.

## Not merged / open
- Auth is unchanged. The legacy API forwards a caller-supplied `Authorization: Bearer`, `X-Provider` and `X-Base-URL` to cloud providers; the structured server has no auth. Both stay as they were. No keys were added.
- `realai/plugins/api_server_cpu.py` and `api_server_backup.py` (already a re-export) were left as they are.
- Making the merged routes or local SDXL the default on :8000 is Travis's decision.
